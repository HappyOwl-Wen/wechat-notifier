# 隐私

原则：100% 本地处理，不联网，程序自己不永久保存聊天内容。

## 处理了什么

| 数据 | 从哪里来 | 保存在哪里 | 保存多久 |
|---|---|---|---|
| 会话名、预览、未读数、时间 | 微信会话列表的 UIA Name（只读） | Listener 内存中的每会话状态（最多 500 个会话，按最近出现淘汰） | 进程生命周期；微信退出或重新附着时清空 |
| 最新消息正文 | 打开中会话的消息单元 UIA Name（只读） | 仅在 `MessageEvent` 中，交给宿主（控制台输出 + 通知） | 程序不保存 |
| **通知内容**（会话名 + 正文或占位符 + 未读数） | `NotificationComposer` | **Windows 通知平台**：横幅，以及通知中心（Windows 把它存在自己的通知数据库 `%LOCALAPPDATA%\Microsoft\Windows\Notifications\wpndatabase.db`） | 直到以下最早发生的一项：你点击或划掉它；你在微信里读了该会话（程序主动撤回）；24 小时过期；电脑重启（`ExpiresOnReboot`）。同一会话的新消息会替换旧通知，新通知里列出这个会话最近的最多 3 条（0.7.0）：这几行只在程序内存里，会话读过、关闭「显示消息内容」或程序退出时清空，不写到任何文件 |
| 通知参数 | 只有 `action=open` 和 tag（会话名 SHA-256 的前 12 字节） | 同上 | 同上 |
| 显示过通知的会话 tag | 只用于「读过后撤回」；点击时 Listener 对可见会话名做同样的哈希来找会话，不保存 tag → 会话名的映射 | 宿主内存，最多 512 个哈希 | 进程生命周期 |
| 去重指纹 | 会话名 + 预览 + 时间 + 未读数的 SHA-256（截断） | 内存 LRU，256 条 | 进程生命周期 |
| 诊断日志 | 组件状态、计数、pid/HWND、延迟、事件来源/类型 | `%LOCALAPPDATA%\WeChatNotifier\logs\listener.log`，1 MB × 3 个文件轮转 | 被轮转覆盖 |
| 通知图标 | 程序内嵌；「以『微信』的名义显示」打开时（0.7.2 起默认）是从电脑上的 `Weixin.exe` 读出的微信图标（只读取它的图标资源，不改动微信） | `%LOCALAPPDATA%\WeChatNotifier\assets\AppIcon-<内容哈希>.png`、`WeixinIcon-<内容哈希>.png`（各保留最近 16 个，每个不到 2 KB） | 直到 `--unregister` 或卸载 |
| **会话头像**（PHASE 3；0.6.2 起保留到磁盘） | 微信窗口在屏幕上时，从会话列表复制头像区域（Level 3） | 内存，以及 `%LOCALAPPDATA%\WeChatNotifier\avatars\<会话 key>.png`（最多 128 个；文件名是会话名的 SHA-256 截断，不含名字） | 30 天没有再复制到这个会话的头像就删除；关闭「显示头像」或「允许临时图片缓存」、点「清除图片缓存」、`--unregister`、卸载时立即删除 |
| **通知图片**（头像、图片预览、生成的首字头像） | 上面的头像；正打开的会话里刚收到的图片 | `%LOCALAPPDATA%\WeChatNotifier\cache\*.png`，随机文件名 | 同一会话的新通知替换旧通知、或会话被读后删除；最迟在通知过期（24 h）或重启后的下次启动时删除；关闭「允许临时图片缓存」（控制台：`--no-image-cache`）时立即删除并不再写入复制来的图片 |
| 设置（PHASE 4） | 托盘菜单 | `%LOCALAPPDATA%\WeChatNotifier\settings.json`：只有开关（true/false），没有聊天数据 | 直到你删除 |
| 开机启动（PHASE 4） | 第一次运行或菜单「开机时启动」 | `HKCU\…\CurrentVersion\Run` 的 `WeChatNotifier` 值：exe 路径 + `--autostart` | 直到你在菜单里关掉或 `--unregister` |
| 错误报告排除（PHASE 4） | 每次启动 | `HKCU\Software\Microsoft\Windows\Windows Error Reporting\ExcludedApplications`：`WeChatNotifier.exe = 1` | 直到 `--unregister` |

诊断日志**从不包含**会话名、消息正文、联系人、窗口标题或图片。这是调用约定，所有调用点在代码审查时都会核对。控制台宿主的 `--no-log` 可以完全关闭文件日志。

## 原生通知带来的变化（PHASE 2）

- **通知文字会离开本程序，交给 Windows**：这是显示原生通知的前提（规格 §5）。数据仍在本机，但存放和显示由 Windows 管理。上表列出了它最长留多久。
- **锁屏**：通知是否显示在锁屏上、是否隐藏内容，由「设置 → 系统 → 通知」决定（全局开关和每个应用的开关，应用名为「WeChat Notifier」）。
- **只显示会话名、不显示正文**：托盘菜单「通知设置 → 显示消息内容」取消勾选（控制台：`--no-preview`）。
- **Windows App SDK 的使用数据**：SDK 会通过 Windows 自己的诊断数据通道（ETW TraceLogging）记录 API 的使用情况。我们核对了源码 `dev/AppNotifications/AppNotificationTelemetry.h`：记录的字段是应用 ID（`WeChatNotifier`）、进程名、是否打包，以及通知内容、tag、group、参数的**长度**，**不包含**通知内容本身。这些数据是否离开电脑，由「设置 → 隐私和安全性 → 诊断和反馈」决定。本程序自己没有任何网络代码。
- **点击后的界面操作**：用户点击通知后，程序会把微信带到前台（微信在托盘里时，通过任务栏的 UI Automation 点击微信的托盘图标，必要时短暂展开「显示隐藏的图标」；微信完全没有运行时才启动 `Weixin.exe`），并可能打开**一个**会话：0.6.3 起像用户一样单击会话列表里的那一行（只在微信是前台窗口、这一行看得见、没有别的窗口挡着时；光标随后回到原处），不行再试 UIA Invoke/Select。除此之外，程序对微信和任务栏只读。托盘菜单「通知设置 → 点击通知时打开对应会话」（控制台：`--no-open-chat`）可以关闭打开会话这一步。

## 头像和图片（PHASE 3）

- 只在微信窗口在屏幕上时复制，而且只复制需要的区域（一个头像、一个图片气泡）；不定时截图，不做 OCR（规格 §4 Level 3、§7）。
- 头像（0.6.2 起）在内存之外还保留在 `avatars` 文件夹，这样程序重启（更新、开机、重新启动监听）后，微信最小化或在托盘时通知里也是真头像；只有头像，没有任何消息图片或文字；30 天没再见到就自动删除。消息图片只写正在显示的通知需要的文件（Windows 只能从文件显示通知图片），通知撤回或过期后删除。
- 图片预览属于消息内容：关闭「显示消息内容」（`--no-preview`）时不显示，也不复制。
- 「允许临时图片缓存」关闭（`--no-image-cache`）：立即删除缓存和保留的头像，不把任何复制来的头像或图片写到磁盘，也不再复制，只用生成的首字头像（不含聊天数据）。「显示头像」「显示图片预览」（`--no-avatar`、`--no-image-preview`）分别关闭头像、图片预览。

## 设置窗口（PHASE 5）

- 单独的进程，只在窗口打开时存在。它读写 `settings.json`，并通过本机窗口消息（`WM_COPYDATA`）请后台程序应用设置、发测试通知、清除缓存、重新启动监听，或取一份状态。状态只有组件状态、时间、计数和延迟（规格 §24），「最后一条消息」只有时间。
- 「复制诊断信息」把同样的纯文本状态放进剪贴板，不含任何消息内容。
- 「群聊消息」开关：判断群聊时，程序在内存里为每个会话记一个「第一个发送者名字的哈希」，见过第二个不同的发送者后只记「是群」。不写磁盘，微信退出时清空。

## 安装（PHASE 6）

- 安装程序把程序文件放到 `%LOCALAPPDATA%\Programs\WeChatNotifier`，创建开始菜单项，并在 `HKCU\…\Uninstall\WeChatNotifier` 写卸载信息（名称、版本、路径、大小）。不需要管理员，不下载任何东西。
- 电脑上缺 Windows App Runtime（微软的通知组件）时，安装程序把 exe 里带的微软安装包为当前用户装上（Windows 自带的 `Add-AppxPackage`），临时解出的安装包装完即删。
- 卸载（设置 → 应用 → 已安装的应用，运行 `WeChatNotifier.exe --uninstall`）：删除上面这些、开机启动项、通知注册和全部通知、图片缓存、错误报告排除项；设置和日志在你同意时一起删除。Windows App Runtime 保留：它是系统共用的组件，别的应用可能也在用。
- 完整的复查记录见 [privacy-review.md](privacy-review.md)。

## 后台程序（PHASE 4）

- **崩溃报告**：程序崩溃时，Windows 错误报告可能收集进程内存（其中可能有刚处理过的聊天文字）并上传给微软。程序每次启动都把自己加入当前用户的错误报告排除列表（`WerAddExcludedApplication`，不需要管理员），所以它的崩溃不会产生或上传报告。程序自己也不写崩溃转储，日志里只记异常类型和 HRESULT。
- **诊断信息**（托盘菜单）：只显示各层状态、时间、计数、延迟和内存（规格 §24）；「最后一条消息」只有时间，没有内容。
- **托盘菜单的隐私开关**：「允许临时图片缓存」关闭时立即删除缓存目录和保留的头像，之后只用生成的首字头像；「立即清除图片缓存」随时可用（同样删除保留的头像）；「调试日志」只增加读取过程的计数和耗时，仍然不含会话名和正文。
- **开机启动**用 Windows 的标准方式（当前用户的 Run 键），在任务管理器 →「启动应用」里能看到并禁用；禁用后程序不会自己改回来。
- 托盘图标的提示文字只有程序状态（如「正在监听微信」），不显示会话名或未读数。

## 不做什么

- 没有任何网络代码。运行时核查（加载 Windows App SDK 之后）：宿主进程 0 个 TCP/UDP 端点，未加载 `ws2_32`、`winhttp`、`wininet`、`System.Net.*`。
- 不注入微信、不 Hook 微信函数、不读微信数据库或网络流量、不修改微信文件和设置。
- UIA 默认只读：`AutoSetFocus=false`。唯一的例外是上面「点击后的界面操作」。
- 没有遥测、崩溃上传或云存储。

## 清除

```powershell
.\src\WeChatNotifier.App\bin\Release\net10.0-windows10.0.19041.0\WeChatNotifier.exe --unregister
```

先让运行中的程序退出，然后删除：开机启动项、HKCU 中的通知注册、通知中心里本程序的所有通知、图片缓存、错误报告排除项。设置、日志和图标在 `%LOCALAPPDATA%\WeChatNotifier\`，之后可以直接删除整个目录。（控制台宿主的 `--unregister` 只删除通知注册、通知和图片。）

## 研究工具（WeChatInspector）

- 默认脱敏：文字只保留形状（`□`/`x`/`◊`）；AutomationId 中的会话显示名（`session_item_<名字>`）和账号 ID 替换为每次运行随机生成的 token。
- 输出只写到仓库内的 `inspector-output\`（已 gitignore）。
- `--show-text` 会写出原文，只应在本机调试时使用，用完请删除。

## 控制台宿主

默认显示原文，因为这就是它的用途：替你看消息。`--redact` 只把**控制台**里的文字换成形状，适合录屏或分享时使用；通知照常显示原文（需要隐藏时用 `--no-preview`）。
